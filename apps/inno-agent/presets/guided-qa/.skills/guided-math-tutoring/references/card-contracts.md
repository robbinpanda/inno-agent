# 卡片内容合同

这里约束的是知识卡片和题目卡片的内容，不是 Agent 的聊天返回格式。Agent 无需在聊天里输出 JSON，也无需声明自己正在执行哪种动作。

卡片写成工作区 Markdown 文件，但字段含义、顺序、单值/列表类型必须与原软件当前卡片模型一一对应。

## 数学公式格式

知识卡片和题目卡片中的所有数学表达必须使用 LaTeX，不限于正文，也包括标题、知识点、核心想法、推导步骤、适用线索、常见错误、题目摘要、解法概览、解题步骤、易错点、如何想到、与当前题目的连接和最终答案。

- 行内公式使用 `$...$`，例如 `$x^2+2x+1=(x+1)^2$`。
- 独立成行或多行公式使用 `$$...$$`，例如：

  ```latex
  $$
  x=\frac{-b\pm\sqrt{b^2-4ac}}{2a}
  $$
  ```

- 分数、根式、幂、乘号、不等号、角度等统一写成 `\frac{a}{b}`、`\sqrt{x}`、`x^2`、`\times`、`\le`、`\angle ABC`、`30^\circ`。
- 不要用 Unicode 或纯文本形式代替数学排版，例如不要写 `x²`、`√x`、`a/b`、`2×3`、`A≤B`；应写成 `$x^2$`、`$\sqrt{x}$`、`$\frac{a}{b}$`、`$2\times3$`、`$A\le B$`。
- 中文解释放在公式定界符之外；公式不要放进 Markdown 反引号代码格式。
- Markdown 卡片中直接保留正常的 LaTeX 反斜杠，不要为了 JSON 再额外双写反斜杠。

## 知识卡片

路径：`learning-cards/knowledge/<slug>.md`

当本轮真正讲清了一个可脱离当前题复用的知识点时，立即创建。一个卡片只讲一个知识点。

原软件字段顺序和类型：

1. `type`：固定为 `knowledge_card`
2. `title`：非空标题
3. `knowledge_point`：本卡唯一知识点
4. `core_idea`：一段话说明定义、原理和直观理解
5. `derivation_steps`：至少一项的步骤列表；每项包含 `title` 和 `content`
6. `when_to_use`：至少一项的适用线索列表
7. `common_mistakes`：常见误区列表；没有时为空列表
8. `connection_to_problem`：该知识点如何支撑当前题的当前一步

Markdown 文件严格按同一顺序呈现：

```markdown
---
type: knowledge_card
title: 等式的基本性质
---

# 等式的基本性质

## 知识点

等式两边同时进行相同运算；若 `$a=b$`，则 `$a+c=b+c$`

## 核心想法

...

## 推导步骤

1. **步骤标题**
   由 `$a=b$` 推出 `$a+c=b+c$`
2. **步骤标题**
   ...

## 什么时候使用

- 适用线索一
- 适用线索二

## 常见错误

- 常见误区一
- 常见误区二

没有常见误区时保留标题，不列项目，对应原软件的空列表。

## 与当前题目的连接

将原方程两边同时减去 `$3$`。
```

自动生成条件：

- 讲解定义、定理、性质、公式及其原理；
- 讲解可复用方法及其识别线索；
- 澄清两个容易混淆的概念；
- 局部纠错过程中实际讲出了可迁移规律。

不自动生成：

- 单次代入或算术；
- 只改一个符号；
- 机械整理式子；
- 只服务当前题、没有迁移意义的过渡。

## 题目卡片

路径：`learning-cards/problems/<slug>.md`

整题完成或学生要求总结时创建。一个卡片只记录一道题。

原软件字段顺序和类型：

1. `type`：固定为 `problem_card`
2. `title`：非空标题
3. `problem_summary`：不遗漏关键条件的题目摘要
4. `solution_overview`：上帝视角的一句话解法路线
5. `solution_steps`：至少一项的连续步骤列表；每项包含从 1 开始的 `step`、`title`、`reasoning` 和 `result`
6. `pitfalls`：本题需要注意的坑点列表；没有时为空列表
7. `how_to_think`：至少一项的识别线索列表，说明如何从题目条件想到上述步骤
8. `final_answer`：最终答案及必要条件

Markdown 文件严格按同一顺序呈现：

```markdown
---
type: problem_card
title: 解一元一次方程
---

# 解一元一次方程

## 题目摘要

求方程 `$2x+3=11$` 的解。

## 解法概览

...

## 解题步骤

1. **步骤标题**
   - 为什么这样做：...
   - 本步结果：$2x=8$
2. **步骤标题**
   - 为什么这样做：...
   - 本步结果：...

## 易错点

- 本题坑点一
- 本题坑点二

没有相关坑点时保留标题，不列项目，对应原软件的空列表。

## 如何想到

- 从条件识别方法的线索一
- 从条件识别方法的线索二

## 最终答案

$x=4$
```

题目卡片从专家视角完整重建整题，不等同于聊天记录摘要。即使对话只讨论了一个断点，也要补齐完整而准确的解题路线，但不得伪称未展示的步骤来自学生。

## 创建与归档的区别

- 创建：满足上述教学触发条件后，立即写入工作区；不需要学生先说“保存”。
- 归档：只有学生明确要求长期保存、归档或以后复习时，才调用 `l2_archive`。
- 归档失败不影响工作区卡片；如实说明卡片已创建但长期归档未完成。
