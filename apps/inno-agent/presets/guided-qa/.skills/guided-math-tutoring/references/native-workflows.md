# Inno Agent 原生工作流

## 能力映射

| 教学需要 | Inno Agent 原生能力 | 使用方式 |
| --- | --- | --- |
| 获取学生的具体判断 | `ask_user_question` | 三个数学选项加“我不知道” |
| 参考既有学习情况 | `get_learner_context` | 需要个性化时先读再教 |
| 记录本轮学习证据 | `record_learning_event` | 仅在学生实际作答或明确表达后记录 |
| 长期保存学习材料 | 工作区文件和 `l2_archive` | 自动创建文件；明确要求后才归档 |
| 召回相关知识 | L3 自动注入或 `l3_recall` | 只使用与当前题直接相关的内容 |
| 阅读题目与手写过程 | 原生视觉、`ocr_image`、`parse_document` | 先客观转录，再进行数学分析 |
| 创建互动练习 | `create_practice_lab` | 交互能明显改善理解时使用 |

## 具体数学检查

可用三个有意义的选项区分学生当前理解时，调用 `ask_user_question`。显示 A、B、C 和“我不知道”，不要在选项文字里泄露哪个正确，也不要写“粗心选项”“概念错误”等标签。

学生作答后，先具体回应这次答案显示出的理解证据，再进入新的讲解或问题。不要只说“回答正确”或“回答错误”。

## 学习者记忆

普通模式下，需要个性化时读取学习者上下文。只有学生实际作答、展示过程或明确表达理解后，才记录学习事件。

- 单次错误不是稳定的人格或能力特征。
- 图片中没写某一步，不等于学生不会该知识。
- 掌握度变化保持小且与证据相称，通常不超过正负 `0.08`。
- 工具参数遵循工具自身 schema，不要求聊天回复附带结构化对象。

## 卡片文件与长期归档

- 知识卡：`learning-cards/knowledge/<slug>.md`
- 题目卡：`learning-cards/problems/<slug>.md`
- 普通练习：`practice/<slug>.md`

卡片达到 [card-contracts.md](card-contracts.md) 的生成条件后，直接创建工作区文件并告知学生路径。不要因为学生没有先说“保存”而跳过创建。

只有学生明确提出保存、归档或以后复习时，才将已创建的卡片交给 `l2_archive`。工作区创建和 L2 归档是两个不同步骤。

## 图像处理

先客观区分并记录：

- 印刷题干和图形标签；
- 学生可见的手写步骤；
- 教师可见的批改符号或文字；
- 无法辨认的区域。

可先使用原生视觉；细字、密集公式或文档页需要时使用 `ocr_image` 或 `parse_document`。转录后再独立求解和比较。

可以判断可见过程的数学合理性，但不能把自己的解法称为学生思路。只有图片中存在批改标记时，才能描述教师判断。图片模糊时请求清晰局部图或键入文本。

一张图含多题时，列出可辨认的题号或简述，让学生选择一题。不要声称已经自动裁题。

## 练习实验室

只有当拖动参数、观察函数图像变化或交互操作能明显帮助理解时，才使用 `create_practice_lab`。创建后告诉学生主文件和运行方法，让学生点击 Run。普通巩固题写入 Markdown 即可。

## 普通模式与简单模式

- 普通模式可以使用 L1/L2/L3 形成连续学习上下文。
- 简单模式中记忆工具可能不可用，但预设、Skill、选择题、图像/OCR 和工作区仍可工作。
- 任何模式都不能因为持久化不可用而跳过题目确认、学生思路确认、针对性讲解或自然总结。
